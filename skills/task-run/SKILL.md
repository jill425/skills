# jill425:task-run — 執行 task

把待辦一張一張做到「完成」。主線只做四件事：選單、派 `jill425:task-executor` 實作、派 `jill425:task-tester` 驗收、彙總。實作與驗收都在 subagent 裡，主線不讀實作細節，連跑很多張 context 也不會越堆越長。

契約：`${CLAUDE_PLUGIN_ROOT}/contract/task-contract.md`。派 subagent 照契約〈派 subagent 的慣例〉；狀態與落點見該專案的 adapter。

**預設持續做**：一張完成就接下一張，直到沒有可做的單。使用者說「只做這張」或指名單張時，做完那張就停。

## 步驟

0. **認後端與上鎖**：依契約認後端。同一個專案同時只跑一個 task-run：鎖檔是 `$(git rev-parse --git-common-dir)/jill425/task-run.lock`。
   - 鎖檔存在且 2 小時內有更新 → 另一個 task-run 正在跑，回報後停下，不動任何單。
   - 不存在或已過期 → 寫入開始時間與目前分支，取得鎖；之後每派出或收回一個 subagent 就 `touch` 一次；步驟 6 結束或暫停時刪除。

1. **選單**：依 adapter 列出待辦。
   - 有單在「執行中」或「修正重做」→ 先接它。
   - 使用者指名 → 用那張。
   - 其餘 → 自動挑：相依皆已完成者優先，同時滿足時編號小的優先。跳過本輪已判定卡住的單與相依它們的單。
   - 沒有可做的單 → 走步驟 6。
   選定後照 adapter 標為「執行中」。跳過或選擇有理由時，照契約〈決策紀錄〉記一筆。

2. **派執行者**：先依契約〈模型分配〉判斷這張單是一般、困難還是文件場景（重做時一律算困難），照該場景設模型與 effort，記一筆決策紀錄。再派一個新的 `jill425:task-executor`，brief 照契約〈派 subagent 的慣例〉第 1 條：
   - 使用者的原始目標（原話）與單號。
   - 要讀的檔：這張單（依 adapter 的讀法）、契約、adapter、專案 `./CLAUDE.md`。
   - 重做時附上：前幾輪的驗收結果原文與前一個執行者的報告；第 3 輪另加「先質疑前提」。
   - 回報格式：照 executor 定義裡的報告格式。

   收回報告後，照慣例第 5 條確認：`git log` 有報告列的 commits、單在「待測」、報告說通過的 Test 方法挑一條關鍵的自己跑一次。對不上就當成「卡住」處理，原因寫「報告與實際不符」。
   - 報告「卡住」→ 這張視為卡住，記一筆決策紀錄，回步驟 1。

3. **派驗收者**：派一個新的 `jill425:task-tester`，模型用跟這張單的執行者不同的那個（契約〈模型分配〉的驗收場景），brief 給單號、契約與 adapter 路徑、這張單的分支。它依 adapter 寫回驗收結果、轉狀態。
   - **全條通過** → 單已標為「完成」。專案 CLAUDE.md 寫明「完成即自動 merge」時，照 adapter §5 merge，並記一筆決策紀錄。走步驟 5。
   - **未過** → 走步驟 4。
   - **⚠ 驗收標準需人工確認** → 這張視為卡住，回步驟 1。

4. **重做**：回步驟 2，派**新的**執行者，brief 附上這一輪的驗收結果。最多驗收 **3 輪**；次數以單上的驗收紀錄計（local-files 數 `### 第 N 輪`、issue 後端數驗收結果 comment），不憑記憶。第 3 輪仍未過，這張視為卡住，回步驟 1。

5. **接下一張**：使用者只要做這張就走步驟 6；否則回步驟 1。

6. **彙總**：回報這一輪（有卡住的單、或某張單重做了 2 輪以上時，最後建議跑 `jill425:task-reflect`）：
   - **完成**：每張的單號、標題、PR／MR 連結（有的話），以及驗收結果裡的「⚠ 缺漏／風險」。
   - **卡住**：每張停在哪一步、為什麼、要人做什麼。
   - **跳過**：因相依卡住的單而沒做的。
   - **範圍外發現**：執行者回報的，提議要不要開新單。
   - **還在待辦**：剩下的單。
   - **決策紀錄**：紀錄檔路徑、這一輪記了幾筆。
   - **待人處理的 PR／MR**：這一輪開出、還沒 merge 的 PR／MR 連結；CI 與 review 留言目前由人處理。

## 中途暫停

使用者說暫停或 session 快結束時：不派新的 subagent；正在跑的 executor 收回報告後就停。單仍是「執行中」，executor 若中途被打斷，下一輪的 executor 從單上的續做錨點與 `git log` 接手。刪掉鎖檔，回報停在哪。
