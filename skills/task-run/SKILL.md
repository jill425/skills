# jill425:task-run — 執行 task

把待辦一張一張做到「完成」。主線只做四件事：選單、派 `jill425:task-executor` 實作、派 `jill425:task-tester` 驗收、彙總。實作與驗收都在 subagent 裡，主線的 context 只放報告。

先讀 `${CLAUDE_PLUGIN_ROOT}/contract/task-contract.md` 與 `${CLAUDE_PLUGIN_ROOT}/contract/dispatch.md`。

**預設持續做**：一張完成就接下一張，直到沒有可做的單。使用者說「只做這張」或指名單張時，做完那張就停。

## 步驟

0. **認後端與上鎖**：照契約〈Task 後端〉認後端。同一個專案同時只跑一個 task-run，鎖檔是 `$(git rev-parse --git-common-dir)/jill425/task-run.lock`：
   - 鎖檔存在且 2 小時內有更新 → 另一個 task-run 正在跑，回報後停下。
   - 不存在或已過期 → 寫入開始時間與目前分支；之後每派出或收回一個 subagent 就 `touch` 一次。
   ✅ 完成：手上有鎖。

1. **選單**：照 adapter 列出待辦，依序挑：
   - 有單在「執行中」或「修正重做」→ 先接它。
   - 使用者指名 → 用那張。
   - 其餘 → 相依都已完成者優先，同時滿足時編號小的優先；跳過本輪已卡住的單與相依它們的單。
   - 單需要人做的操作（契約 invariant 4、5）→ 直接判定卡住：把原因與要人做的事寫成這張單的續做錨點並 commit，不派執行者。
   - 沒有可做的單 → 走步驟 6。
   選定後照 adapter 標為「執行中」，用 `${CLAUDE_PLUGIN_ROOT}/scripts/log-decision.sh` 記下選了哪張、跳過哪張與原因。
   ✅ 完成：有一張「執行中」的單，或確定沒有可做的單；這一步判定卡住的每張單，單上都有續做錨點。

2. **派執行者**：照 `dispatch.md`〈模型分配〉判斷這張單的場景，設模型與 effort，記一筆決策紀錄。派一個新的 `jill425:task-executor`，brief 照 `dispatch.md`〈慣例〉：
   - 使用者的原始目標（原話）與單號。
   - 要讀的檔：這張單、契約、adapter、專案 `./CLAUDE.md`。
   - 重做時附上前幾輪的驗收結果與前一個執行者的報告；第 3 輪另加「先質疑前提」。
   - 回報格式：executor 定義裡的報告格式。

   收回報告後自己確認：`git log` 有報告列的 commits、單在「待測」、報告說通過的 Test 方法挑一條關鍵的自己跑一次。對不上就判定卡住，原因寫「報告與實際不符」。報告「卡住」時也判定卡住。卡住都記一筆決策紀錄，回步驟 1。
   ✅ 完成：單在「待測」且核對相符，或已判定卡住。

3. **派驗收者**：派一個新的 `jill425:task-tester`，模型照 `dispatch.md`〈模型分配〉的驗收場景（跟執行者不同），brief 給單號、契約與 adapter 路徑、這張單的分支。
   - **全條通過** → 單已標為「完成」。專案 CLAUDE.md 寫明「完成即自動 merge」時，照 adapter §5 merge，記一筆決策紀錄。走步驟 5。
   - **未過** → 走步驟 4。
   - **⚠ 驗收標準需人工確認** → 判定卡住，回步驟 1。
   ✅ 完成：單上有這一輪的驗收結果。

4. **重做**：輪數以單上的驗收紀錄計（local-files 數 `### 第 N 輪`、issue 後端數驗收結果 comment）。還沒到契約〈生命週期〉的卡住條件就回步驟 2，派**新的**執行者；到了就判定卡住，回步驟 1。
   ✅ 完成：已派出新的執行者，或已判定卡住。

5. **接下一張**：使用者只要做這張就走步驟 6；否則回步驟 1。

6. **彙總**：刪掉鎖檔，回報這一輪：
   - **完成**：每張的單號、標題、PR／MR 連結（有的話），以及驗收結果裡的「⚠ 缺漏／風險」。
   - **卡住**：每張停在哪一步、為什麼、要人做什麼。
   - **跳過**：因相依卡住的單而沒做的。
   - **範圍外發現**：執行者回報的，提議要不要開新單。
   - **還在待辦**：剩下的單。
   - **決策紀錄**：紀錄檔路徑、這一輪記了幾筆。
   - **待人處理的 PR／MR**：這一輪開出、還沒 merge 的連結；CI 與 review 留言由人處理。
   有卡住的單、或某張單重做了 2 輪以上時，最後建議跑 `jill425:task-reflect`。
   ✅ 完成：彙總涵蓋這一輪碰過的每張單，鎖檔已刪。

## 中途暫停

使用者說暫停或 session 快結束時：不再派新的 subagent；正在跑的 executor 收回報告後就停。單仍是「執行中」，下一輪的 executor 從單上的續做錨點與 `git log` 接手。刪掉鎖檔，回報停在哪。
