# jill425:task-dev — 把一張單做到完成

你是執行者：一次一張單，從「執行中」做到驗收通過。開發步驟只有這一份。使用者直接叫用時你在主線；被 `jill425:task-multi-run` 派出時你是 subagent，看不到那段對話，依據只有 brief、這張單和 repo。兩者只差在〈需要人決定時〉與〈交回〉。

先讀：
- `${CLAUDE_PLUGIN_ROOT}/contract/task-contract.md`，照它〈Task 後端〉認後端，再讀那個 adapter。
- 指定的單（照 adapter 讀全文與所有既有記錄）與專案 `./CLAUDE.md`。
- 要寫 code 時讀 `${CLAUDE_PLUGIN_ROOT}/contract/principles.md`；單是 bug、調查、效能或原型時，讀 `${CLAUDE_PLUGIN_ROOT}/contract/ticket-kinds.md` 對應的一節；派 subagent 前讀 `${CLAUDE_PLUGIN_ROOT}/contract/dispatch.md`。

## 步驟

1. **對錨與切片**：先上鎖：`$(git rev-parse --git-common-dir)/jill425/task-<id>.lock` 在 2 小時內有更新，表示另一個 session 正在做這張單，回報後停下；否則寫入開始時間與分支，之後每次 commit 後 `touch` 一次，交回時刪掉。
   讀該單全文與所有既有記錄；單有續做錨點就從它寫的下一步接著做。相依的前一張已完成但還沒合併時，照 adapter §5 從它的分支開工。照 adapter 把單標為「執行中」。
   接著讀這張單會動到的 code 與現有測試，**以 code 為準**（invariant 6）：跟單上的背景或做法對不上時，記一筆〈推翻假設〉，照實際的 code 做。
   把單切成幾個**切片**，每個切片做完都能實際跑起來看到結果。
   ✅ 完成：能複述目標、範圍外與每一條 Test 方法；要改的每個地方都指得出 `檔案:行`；每個切片說得出「做完能看到什麼在跑」。

2. **切片循環**：一個切片一輪。
   - **實作**：照 `## 做法`、專案 `./CLAUDE.md` 的慣例、`principles.md`。每個行為先寫測試、跑出紅燈（斷言失敗），再實作轉綠，至少 commit 一次，格式照契約〈git commit〉。要新增或改變跨模組的介面、新增模組，或做沒有前例的架構決定時，先叫用 `jill425:code-design`。改動系統結構時用 `jill425:doc-arch` 同步 `docs/arch/`。
   - **bug 單**：先跑 `## 背景` 的重現，確認現在仍會錯。列出假設，每次做一個能排除最多可能的觀察；每一處修改都要有執行期證據支持，被推翻的假設連同它帶來的改動一起拿掉。
   - **調查、效能、原型單**：照 `ticket-kinds.md` 做，產出寫進單上的〈結論〉。
   - **回歸**：每個 commit 之後，在背景跑專案 `./CLAUDE.md` 的 DoD 指令。紅了就先修，修到綠才進下一個切片。
   - **計畫對照**（調查與原型單跳過）：切片結束時叫用 `jill425:check-plan`，參數是單號與這個切片最後一個 commit 的 sha。它在背景跑；接著做下一個切片。
   - **處理發現**：報告回來後，在當前這一小步告一段落時照〈處理發現〉逐條處置。
   - **偏離與決策**：實作跟 `## 做法` 不同，或在兩種以上可行做法中選了一個（影響介面、資料結構、依賴、模組歸屬），寫一筆〈偏離做法〉或〈決策〉執行備註。
   ✅ 完成：每個切片的 DoD 指令全綠；每份計畫對照報告的每一條都有處置。

3. **收尾**（一張單一次；調查與原型單跳過）：對這張單相對基底的完整 diff：
   - 叫用 `code-review`（level low）與 `simplify`，對照 `principles.md` 逐條檢查；碰 token、個資、DB 寫入時加 `security-review`。
   - 改到對外介面（API 欄位、訊息格式）、DB schema，或被 3 個以上模組 import 的模組時，叫用 `jill425:code-impact`。它證出的風險與驗證過的攻擊發現當場修，便宜的做成回歸測試；修法會改變行為時照〈需要人決定時〉。
   - **簡單優先**：問「這份 diff 刪掉哪些部分後，Test 方法仍然全過？」，刪掉答得出來的部分，連同只為它而寫的測試。
   - 程式類單照 `${CLAUDE_PLUGIN_ROOT}/contract/tdd-evidence.md` 自己做一次反向驗證。
   - 重跑全部 Test 方法與 DoD 指令，都以真實依賴跑。
   ✅ 完成：review 與 code-impact 沒有未處理的發現；Test 方法與 DoD 重跑全綠。

4. **送驗**：寫該寫的執行備註，照 adapter 把單轉為「待測」，含該後端要求的動作（push、開 PR／MR）。派一個新的 `jill425:task-tester`，模型照 `dispatch.md`〈模型分配〉的驗收場景，brief 只有這四項：單號、契約與 adapter 的路徑、這張單的分支、回報格式（契約〈驗收結果〉）。派出時記一筆決策紀錄，寫明驗收者的模型。
   - **全條通過** → 單已標為「完成」。走步驟 5。
   - **未過** → 照驗收結果的現象與修復原地修，重跑 Test 方法與 DoD，再派新的 tester。輪數以單上的驗收紀錄計；第 3 輪修之前，先寫下前幾輪修法共同依賴的那句前提，找一個「前提錯了結果就會不同」的觀察實際跑，前提被推翻就換方向，記一筆〈推翻假設〉。
   - **3 輪仍未過**，或驗收者標了「⚠ 驗收標準需人工確認」→ 照〈需要人決定時〉。
   ✅ 完成：單上有這一輪的驗收結果；單在「完成」，或已照〈需要人決定時〉停下。

5. **交回**：刪掉鎖檔，照〈交回〉。
   ✅ 完成：改動已進版控，能從單追到；驗收結果列的「單上沒要求的 code」已交給使用者決定；鎖檔已刪。

## 處理發現

計畫對照、回歸、收尾 review 的每一條發現，照下表處置，並用 `${CLAUDE_PLUGIN_ROOT}/scripts/log-decision.sh` 記一行（採用、不處理附理由、開新單）。報告的 sha 跟目前 HEAD 不同時，先確認那一條在 HEAD 上還成立。

| 發現 | 處置 |
|---|---|
| 回歸紅了 | 立刻修 |
| 單內的錯，證據到「跑過」：code 跟單上寫的行為不符、少了某條 Test 方法的測試 | 直接修，commit |
| 證據只到推測或指認 | 10 分鐘內自己跑出證據：證實了照上一列，沒證實記「不處理：未證實」 |
| 單上沒要求的 code | 說不出「不做會讓單上哪一句出錯」的刪掉；想留下的照〈需要人決定時〉 |
| 會改變行為、API、schema 或資料語意；兩份報告互相衝突 | 照〈需要人決定時〉 |
| 超出這張單的範圍 | 記成範圍外發現，交回時列出 |

修完由回歸與下一個切片的計畫對照確認，同一個切片只對照一次。同一類發現出現第二次，交回時建議用 `jill425:rule-enforce`。

## 需要人決定時

適用：破壞性操作與正式環境（invariant 4、5）、需求本身有矛盾、〈處理發現〉指到這裡的發現、驗收 3 輪仍未過、「⚠ 驗收標準需人工確認」。

1. 停在當前這一小步，把這個決定之前的工作 commit。
2. 寫續做錨點（契約〈執行期產出〉），並記一筆決策紀錄。
3. 問：每個問題附選項、你的建議，以及這個決定牽涉的資料表、API、模組。
   - **你在主線**：直接問使用者，等到回答才往下做。
   - **你是 subagent**：刪掉鎖檔，把問題當作報告交回，結果寫「等待決定」；收到回答後重新上鎖，從續做錨點接著做。
4. 得到回答後，使用者的回答就是同意：會改變目標、做法或 Test 方法的，照 `jill425:task-plan`〈修改既有單的 Test 方法〉第 3 步更新單，寫一筆〈範圍變動〉或〈決策〉執行備註，再接著做。

## 交回

你在主線時用同樣的項目向使用者回報；你是 subagent 時照下面的格式交回。只寫實際做過、跑過的事；沒跑的寫「沒跑」。

```
單號：#<id> <標題>
結果：完成｜等待決定
分支與 commits：<分支名>；<sha 與 subject，一行一個>
PR／MR：<連結或「無」>
驗收：第 <N> 輪 <通過｜未過>；<驗收者的模型>
Test 方法：<每條一行：條文 — 本機實跑的指令與結果>
發現與處置：<計畫對照、收尾 review、code-impact 各幾條；修了什麼、不處理什麼與理由>
單上沒要求的 code：<驗收結果列出的每一項 — 建議刪或留；沒有就寫「無」>
執行備註：<寫了哪幾筆、類別；偏離做法與決策逐筆一行摘要>
結論：<調查、效能、原型單：〈結論〉的摘要；其他單省略>
等待決定：<每個問題：選項、建議、牽涉的資料表／API／模組；沒有就省略>
範圍外發現：<沒有就省略>
```

## 範圍

- **只做這張單**：其他單的檔案與狀態維持原樣；範圍外的問題記成範圍外發現。
- **Test 方法不適用時**：寫〈驗收標準需重新確認〉執行備註，照樣把能做的做完。
- **merge 留給人**：專案 `./CLAUDE.md` 寫明「完成即自動 merge」時，你在主線才照 adapter §5 merge；你是 subagent 時由 `jill425:task-multi-run` 核對後 merge。
