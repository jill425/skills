# jill425:task-multi-run — 派單與彙總

把待辦做到「完成」，預設一次一張，符合〈同時做〉的條件時最多同時 3 張。主線只做四件事：選單、選模型並派出執行者、轉達需要人決定的問題、彙總。開發與驗收都在 subagent 裡照 `jill425:task-dev` 進行，主線的 context 只放報告。

先讀 `${CLAUDE_PLUGIN_ROOT}/contract/task-contract.md` 與 `${CLAUDE_PLUGIN_ROOT}/contract/dispatch.md`。

**預設持續做**：一張完成就接下一張，直到沒有可做的單。使用者指名單張時，做完那張就停。

**無人值守**：使用者說了不要問，或這一輪是 `claude -p` 跑的。這時沒有人能回答問題，步驟 3 照無人值守那一條走。

## 步驟

0. **認後端**：照契約〈Task 後端〉認後端。
   ✅ 完成：知道這個專案的單在哪、怎麼讀。

1. **選單**：照 adapter 列出待辦，依序挑：
   - 鎖檔還有效的單（`$(git rev-parse --git-common-dir)/jill425/task-<id>.lock` 在 2 小時內有更新）→ 另一個 session 正在做，跳過。
   - 有單在「執行中」或「修正重做」→ 先接它。
   - 使用者指名 → 用那張。
   - 其餘 → 相依都已完成者優先，同時滿足時編號小的優先；跳過本輪已卡住的單、相依它們的單，以及步驟 3 判定受同一個決定影響的單。
   - 單需要人做的操作（契約 invariant 4、5）→ 直接判定卡住：把原因與要人做的事寫成這張單的續做錨點並 commit，不派執行者。
   - 沒有可做的單 → 走步驟 5。
   選定後照 adapter 標為「執行中」，用 `${CLAUDE_PLUGIN_ROOT}/scripts/log-decision.sh` 記下選了哪張、跳過哪張與原因。
   ✅ 完成：有一張「執行中」的單，或確定沒有可做的單；這一步判定卡住的每張單，單上都有續做錨點。

2. **派出執行者**：照 `dispatch.md`〈模型分配〉判斷這張單的場景，設模型與 effort，記一筆決策紀錄。派一個通用 subagent，brief 照 `dispatch.md`〈慣例〉：
   - 使用者的原始目標（原話）與單號。
   - 做法：叫用 `jill425:task-dev` 做這張單；叫不到就讀 `${CLAUDE_PLUGIN_ROOT}/skills/task-dev/SKILL.md` 照做。
   - 你被派出時用的模型（它選驗收模型時要用），以及這一輪是不是無人值守。
   - 回報格式：`task-dev`〈交回〉的格式。
   ✅ 完成：執行者已派出；同時做時每個執行者都有自己的 worktree。

3. **收回報告**：
   - **結果「完成」** → 自己確認：`git log` 有報告列的 commits、單在「完成」、單上有通過的驗收結果。對不上就叫同一個 subagent 接著做完（照 `dispatch.md`〈慣例〉3）；第二次仍對不上才判定卡住，原因寫「報告與實際不符」。專案 `./CLAUDE.md` 寫明「完成即自動 merge」時，照 adapter §5 merge，記一筆決策紀錄。
   - **結果「等待決定」，有人在場** → 立刻把問題連同選項與建議原樣問使用者，等到回答；這段期間不派會碰到同一批資料表、API、模組的單，判斷不出來就當作會碰到。回答傳回同一個 subagent，它從續做錨點接著做，回到本步驟開頭。
   - **結果「等待決定」，無人值守** → 判定卡住。記下這個決定牽涉的資料表、API、模組；之後選單時，會碰到同一批的單一起跳過，判斷不出來就當作會碰到。
   卡住都記一筆決策紀錄。
   ✅ 完成：單在「完成」且核對相符，或已判定卡住。

4. **接下一張**：使用者只要做這張就走步驟 5；否則回步驟 1。

5. **彙總**：回報這一輪：
   - **完成**：每張的單號、標題、PR／MR 連結（有的話），以及驗收結果裡的「⚠ 缺漏／風險」。
   - **單上沒要求的 code**：驗收結果列出的每一項，等使用者決定刪或留。
   - **卡住**：每張停在哪一步、要人決定或做什麼。
   - **跳過**：因相依、或受同一個決定影響而沒做的單。
   - **範圍外發現**：執行者回報的，提議要不要開新單。
   - **還在待辦**：剩下的單。
   - **決策紀錄**：紀錄檔路徑、這一輪記了幾筆。
   - **待人處理的 PR／MR**：這一輪開出、還沒 merge 的連結；CI 與 review 留言由人處理。
   有卡住的單、或某張單驗收了 2 輪以上時，最後建議跑 `jill425:task-reflect`。
   ✅ 完成：彙總涵蓋這一輪碰過的每張單。

## 同時做

下面三條都成立，才同時派出幾張單，最多 3 張；否則一次一張。

- **issue 後端**：local-files 的單檔與 `INDEX.md` 跟 code 一起進版控，同時做會互相衝突。
- **專案寫了平行開發的方式**：專案 `./CLAUDE.md` 寫明每個 worktree 用哪個資料庫與 port。
- **單之間互不影響**：彼此沒有相依，每張的 `## 做法` 都寫了影響範圍，而且兩兩不重疊。

每個執行者在自己的 worktree 做（`dispatch.md`〈慣例〉4），brief 加上 worktree 的路徑、它的資料庫與 port。報告各自照步驟 3 處理，收回一張就回步驟 1 補派下一張。

## 中途暫停

使用者說暫停或 session 快結束時：不再派新的 subagent；請正在跑的執行者寫續做錨點後停下。單仍是「執行中」，下一次由 `jill425:task-dev` 或 `jill425:task-multi-run` 從單上的續做錨點與 `git log` 接手。回報停在哪。
