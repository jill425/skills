# jill425:code-impact — 改動會壞到哪

列出呼叫端不是重點，grep 一秒就有。要找的是 grep 看不到的破壞：回傳的 JSON 欄位、DB 欄位、訊息格式、另一個語言讀同一份資料、feature flag、三層以外的下游。

一篇聽起來對的分析不管真假讀起來都一樣有說服力，所以不交分析，交證明：找出整個改動安全所依賴的那一兩個事實，用跑起來的 code 證明它。每個事實標證據等級（推測／指認／推演／跑過／重現，定義在 `${CLAUDE_PLUGIN_ROOT}/contract/task-contract.md`〈執行期產出〉），10 分鐘內寫得出腳本驗證的推到「跑過」。

## 步驟

1. **讀改動**：該單相對基底的完整 diff，新增、修改、刪除了哪些符號，行為上跟以前差在哪——包括 diff 沒寫明的部分（預設值、錯誤路徑、順序、時序）。
   ✅ 完成：說得出改動前後行為差在哪，一句一個。

2. **找那個關鍵事實**：多數看起來危險的改動，安全只靠一個事實（例：「這個欄位只有後台讀，App 不讀」「舊資料都已經有值，NOT NULL 不會炸」）。先找它；它成立，大部分風險一次排除。
   ✅ 完成：寫得出「這個改動安全，是因為 ___」。

3. **看 grep 看不到的地方**：呼叫的函式庫原始碼與鎖定版本；執行時機（async、交易邊界、排程、重試）；對外契約的消費者——API 文件、前端或 App 怎麼解析欄位、協議或封包規格文件；DB 欄位被哪些查詢、報表、排程讀；設定與環境變數在各環境的值（只讀，不碰 prod 寫入）。
   ✅ 完成：每個消費者都有出處（`file:line`、文件段落），沒找到也寫「查了哪裡、沒找到」。

4. **評估每個風險**：寫出發生機率與發生時的代價。確認的列為風險；查過沒事的另列為已排除，寫原因。每個呼叫端與 API 都附 `檔案:行`。
   ✅ 完成：每個風險都歸進「風險」或「已排除」，各附出處。

5. **證明關鍵事實**：寫一個呼叫真實 code（或對本機開發資料庫查真實資料）的小腳本或測試，跑它，貼輸出。放在 scratchpad，不進 repo，除非它值得留成正式測試。
   ✅ 完成：關鍵事實到「跑過」或「重現」，或明寫「未證明」與卡在哪。

6. **攻擊**：同時派兩個 subagent，各自試著把這個改動弄壞。模型照 `${CLAUDE_PLUGIN_ROOT}/contract/dispatch.md`〈模型分配〉的攻擊者 A／B；預設兩人用不同模型，不同模型的盲點不同，抓到的 bug 也不同。每個攻擊者在自己的 worktree 工作：`git worktree add --detach <scratchpad>/atk-<n> HEAD`，再把還沒 commit 的改動帶過去（`git diff HEAD --binary | git -C <scratchpad>/atk-<n> apply`，未追蹤的新檔直接複製）。兩個攻擊者分工：
   - **攻擊者 A：邊界與異常輸入**。空值、極端值、格式錯誤、權限不足、重複呼叫、同時呼叫。
   - **攻擊者 B：整合與狀態**。呼叫端與下游、DB schema 與既有資料、序列化格式、重試與部分失敗、跟其他模組的約定。

   給兩人相同的資料：改動的目的（步驟 1 的結論）、diff、這份分工，以及這段指示：
   > 把這個改動弄壞。每個發現都要附：標題、實際跑的指令、印出的輸出、改動目的要求的輸出。重現用的腳本只放在你自己的 worktree。沒有實際跑過的不要報，風格、命名、結構、要等未來改動才會出現的風險都不算。找不到也是有效結果。

   ✅ 完成：兩個攻擊者都回報了，或回報找不到。

7. **驗證發現**：主線把每個發現的指令重跑一次。輸出真的顯示失敗、而且違反改動的目的，才保留；同一個根因的合併成一條。其他的丟掉，記下每個攻擊者丟了幾條、為什麼。最後移除攻擊者的 worktree：`git worktree remove --force <scratchpad>/atk-<n>`。
   ✅ 完成：每條保留的發現都有主線自己重跑的輸出。

## 交回

- **改了什麼**：含不明顯的部分。
- **安全是因為**：那個事實、證據等級、證明輸出；證不出來寫「未證明」。
- **風險**：怎麼壞、`file:line`、機率與代價、怎麼驗；重要的附證明輸出。
- **已排除**：查了什麼、為什麼沒事。
- **攻擊結果**：兩個攻擊者各用了哪個模型；每條保留的發現附指令、輸出、違反了什麼、哪個攻擊者找到；以及每個攻擊者丟掉幾條、為什麼。沒有保留的就寫「沒有驗證過的發現」。
- **合併前**：最便宜能抓到真實問題的測試或重現，附腳本。

由 `jill425:task-dev` 在收尾叫用時：確認的風險與保留的攻擊發現當場修掉，能便宜做成測試的就加成回歸測試，再重跑 Test 方法；證不出的照上面格式附在送驗回報（issue 後端寫進 PR／MR 描述）。
