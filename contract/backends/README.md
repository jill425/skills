# Task 後端 adapter

一個後端一檔：`github-issues.md`、`gitlab-issues.md`、`local-files.md`。adapter 只寫**機制**（指令、落點、狀態怎麼表示）；規則與格式在 `../task-contract.md`。狀態名一律用契約的字（如「完成」），再寫它在這個後端等於什麼動作。

## 新增後端時，adapter 要回答的六件事

1. 單存在哪；怎麼列出待辦；怎麼讀一張的全文與既有記錄。
2. 怎麼開一張新單（含標題與 body 的落點）。
3. 執行備註、結論、驗收結果各寫到哪，是覆寫還是追加。
4. 契約〈生命週期〉的五個狀態各用什麼表示、怎麼轉。
5. 「完成」在這個後端是什麼動作；設定自動 merge 時用什麼指令；相依的前一張還沒合併時，下一張怎麼開工。
6. 這個後端的命名與關聯慣例（分支、編號、連結）。

寫完後在 `../task-contract.md`〈Task 後端〉與 `projects.template.md` 補上這個後端的名字。
